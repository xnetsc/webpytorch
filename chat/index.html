Running code from a reply

A reply's Python blocks get a ▶ button. The code runs in its own Python — a separate runtime from the one holding the model, so nothing it does can disturb a conversation.

With this on, the model is told the runtime exists and can run code, add modules or restart it in the middle of an answer — and is asked again with what came back, so it can compute instead of guessing. Every call and its result is shown in the reply. Off by default: a model acting on its own initiative is a different thing from one that answers, and only models whose chat template documents tools can use it at all.

Remote diagnostics

When something goes wrong on your machine and not on ours, this is how the two can be compared. The page joins an MQTT topic and answers a fixed set of questions about itself — which backend it got, what is cached, what errored. Give whoever is helping you the topic below and they can ask.

It cannot run code. The broker is public, so anyone who learns your topic could send it requests; it answers only the fixed list (ping, diag, state, caches, errors, perf) and never your conversations, your files or anything you typed. Point it at your own broker, or switch it off, if even that is more than you want to share.
